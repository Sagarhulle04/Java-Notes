Definition: Object-Oriented Programming (OOP) is a programming approach that organizes software around objects containing state (data) and behavior (methods). Java is class-based and supports OOP through classes, objects, inheritance, polymorphism, encapsulation, and abstraction.
Learning path: Understand class and object first, then learn the four pillars, then constructors and Java keywords, and finally practice output-based questions.

1. Foundations: classes and objects

The building blocks behind every object-oriented Java program.

Class

Definition: A class is a blueprint that declares the fields and methods its objects can have.
  • Why needed: It groups related data and behavior into one reusable design.
  • How it works: A class declaration defines members; creating an object allocates an instance with its own instance-field values.
  • Rule: A top-level public class must be saved in a file with the same name, such as Student.java.

Object

Definition: An object is a runtime instance of a class. It has identity, state, and behavior.
  • State: Current field values, such as a student's name.
  • Behavior: Operations provided by methods, such as study().
  • Identity: The particular object, even if another object has equal field values.
JAVA
class Student {
    String name;
    int age;

    void introduce() {
        System.out.println("I am " + name + ", age " + age);
    }
}

public class Main {
    public static void main(String[] args) {
        Student s1 = new Student();
        s1.name = "Asha";
        s1.age = 21;
        s1.introduce();
    }
}
I am Asha, age 21

Execution: new Student() creates an instance; s1 stores its reference; assignments set field values; introduce() reads those values and prints the message.

Common mistake: A reference variable is not the object itself. It refers to an object. Multiple references can refer to the same object.

Fields, methods, and new

  • Field: A variable declared in a class to hold object or class state.
  • Method: A named block of code that defines behavior and can accept parameters and return a value.
  • new: Commonly creates an object and invokes its constructor; it returns a reference to the created object.
  • Default field values: Instance fields get defaults such as 0, false, and null. Local variables do not get automatic default values and must be definitely assigned before use.

2. The four pillars of OOP

Learn the purpose of each pillar and how Java expresses it.

2.1 Encapsulation

Definition: Encapsulation bundles data and the methods that operate on it, while controlling access to an object's internal state.

Why it matters: It protects invariants, prevents uncontrolled changes, and lets a class change its implementation without changing its public API.

JAVA
class BankAccount {
    private double balance;

    public void deposit(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("Amount must be positive");
        }
        balance += amount;
    }

    public double getBalance() {
        return balance;
    }
}

public class Main {
    public static void main(String[] args) {
        BankAccount account = new BankAccount();
        account.deposit(500);
        System.out.println(account.getBalance());
    }
}
500.0

How it works: balance is private, so callers cannot assign it directly. They must use the public method, which validates the amount before updating the value.

Interview tip: Encapsulation is not simply “using getters and setters.” It is about controlled access and preserving valid state. A setter that accepts every value may weaken encapsulation.

2.2 Inheritance

Definition: Inheritance lets a class (subclass/child) extend another class (superclass/parent), inheriting accessible members and optionally adding or overriding behavior.

Why it matters: It models an “is-a” relationship and supports reuse and runtime polymorphism.

JAVA
class Animal {
    void sound() {
        System.out.println("Animal makes a sound");
    }
}
class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}
public class Main {
    public static void main(String[] args) {
        Dog dog = new Dog();
        dog.sound();
    }
}
Dog barks

Rules: Java classes have one direct superclass (single class inheritance), but a class can implement multiple interfaces. Constructors are not inherited. Private members are not directly accessible in subclasses.

Common mistake: Do not use inheritance just to avoid copying a few lines. If the relationship is “has-a” rather than “is-a,” composition is often a better choice.

2.3 Polymorphism

Definition: Polymorphism means “many forms”: the same operation or reference type can lead to different behavior depending on the overload selected or the runtime object's class.
Compile-time: overloading

Same method name, different parameter lists. The compiler chooses the applicable overload.

Runtime: overriding

A subclass supplies an implementation of an inherited instance method. The runtime class determines which override runs.

JAVA
class Printer {
    void print(int value) {
        System.out.println("Integer: " + value);
    }
    void print(String value) {
        System.out.println("Text: " + value);
    }
}
class Shape {
    double area() { return 0; }
}
class Circle extends Shape {
    @Override
    double area() { return Math.PI * 2 * 2; }
}
public class Main {
    public static void main(String[] args) {
        new Printer().print(7);
        Shape shape = new Circle();
        System.out.printf("Area: %.2f%n", shape.area());
    }
}
Integer: 7 Area: 12.57

Important: Overloading is resolved using compile-time types and argument signatures. Overridden instance methods use dynamic dispatch. Static methods are hidden rather than overridden.

2.4 Abstraction

Definition: Abstraction exposes essential operations while hiding unnecessary implementation details.

Java commonly achieves abstraction through abstract classes and interfaces. A caller can use an agreed contract without knowing how each implementation performs the work.

JAVA
interface PaymentMethod {
    void pay(double amount);
}
class CardPayment implements PaymentMethod {
    public void pay(double amount) {
        System.out.println("Paid ₹" + amount + " by card");
    }
}
public class Main {
    public static void main(String[] args) {
        PaymentMethod payment = new CardPayment();
        payment.pay(250);
    }
}
Paid ₹250.0 by card

Why useful: A checkout service can depend on PaymentMethod rather than a specific payment provider. New implementations can be introduced with less change to client code.

Remember: Abstraction focuses on what an object offers; encapsulation focuses on protecting and controlling how its state is accessed.

3. Constructors, keywords, and object relationships

Constructors

A constructor initializes a newly created object. It has the same name as the class and no return type—not even void.

JAVA
class Employee {
    String name;
    Employee() { this("Unknown"); } // delegates to another constructor
    Employee(String name) { this.name = name; }
}
public class Main {
    public static void main(String[] args) {
        System.out.println(new Employee().name);
        System.out.println(new Employee("Mira").name);
    }
}
Unknown Mira
  • If no constructor is declared, the compiler may provide a default no-argument constructor.
  • Once you declare any constructor, Java does not automatically add that default constructor.
  • this(...) invokes another constructor in the same class; super(...) invokes a superclass constructor. In conventional Java source, either constructor invocation must be the first statement; newer Java releases have carefully scoped flexible constructor-body rules, so follow the language version in use.
  • Constructors are not inherited and cannot be overridden.

Association, aggregation, and composition

Association

A general relationship between independent objects.

Example: Doctor treats Patient.

Aggregation

A whole-part relationship where the part can exist independently of the whole.

Example: Team has Players.

Composition

A strong ownership relationship where the part's lifecycle is typically controlled by the whole.

Example: Order has OrderLines.

Design tip: Prefer composition when it gives a clearer, more flexible model than inheritance. These relationship labels describe design intent; Java does not enforce aggregation or composition with special keywords.

5. Real-world examples

How OOP concepts map to applications you may build.

Example 1 — Banking application (encapsulation)

Scenario: A bank account must never be changed by arbitrary code to an invalid balance.

Solution: Keep the balance private and expose validated operations. This small example models deposits; production banking requires currency-safe arithmetic, authentication, concurrency controls, audit logs, and transactional persistence.

JAVA
class Account {
    private int balanceInPaise;
    public void deposit(int paise) {
        if (paise <= 0) throw new IllegalArgumentException();
        balanceInPaise += paise;
    }
    public int balanceInPaise() { return balanceInPaise; }
}
public class Main {
    public static void main(String[] args) {
        Account a = new Account();
        a.deposit(12500);
        System.out.println(a.balanceInPaise());
    }
}
12500

Why useful: The account owns the rule for valid deposits, so callers cannot bypass it through a public field.

Example 2 — E-commerce checkout (abstraction + polymorphism)

Scenario: Checkout should support multiple payment methods without containing provider-specific logic everywhere.

JAVA
interface Payment {
    void pay(int rupees);
}
class UpiPayment implements Payment {
    public void pay(int rupees) {
        System.out.println("UPI payment: ₹" + rupees);
    }
}
class CardPayment implements Payment {
    public void pay(int rupees) {
        System.out.println("Card payment: ₹" + rupees);
    }
}
public class Main {
    static void checkout(Payment method) { method.pay(499); }
    public static void main(String[] args) {
        checkout(new UpiPayment());
        checkout(new CardPayment());
    }
}
UPI payment: ₹499 Card payment: ₹499

Why useful: The checkout method depends on the Payment contract and can work with different implementations. Real payment code must use a secure, trusted payment provider and handle failures safely.

Example 3 — Employee management (inheritance + overriding)

Scenario: Different employee types calculate bonuses differently, but the application handles them through one base type.

JAVA
class Employee {
    double bonus() { return 0; }
}
class Manager extends Employee {
    @Override double bonus() { return 15000; }
}
class Developer extends Employee {
    @Override double bonus() { return 10000; }
}
public class Main {
    public static void main(String[] args) {
        Employee[] staff = {new Manager(), new Developer()};
        for (Employee e : staff) {
            System.out.println(e.bonus());
        }
    }
}
15000.0 10000.0

Why useful: The loop does not need to check each employee's concrete class. Runtime polymorphism chooses the appropriate override. Real bonus rules would use validated data and explicit business policies.

6. Interview questions and answers

Select a question to reveal or hide its answer. Each answer includes key points and a follow-up.

01
What is OOP in Java?
BeginnerFundamentals
⌄

Answer

  1. OOP stands for Object-Oriented Programming.
  2. It organizes code around objects that combine state and behavior.
  3. Java uses classes as blueprints for objects.
  4. Its core OOP principles are encapsulation, inheritance, polymorphism, and abstraction.
  5. OOP can improve modularity, reuse, and maintainability when the design fits the problem.
Follow-up: Is Java a purely object-oriented language?
Answer: No. Java has primitive types such as int and boolean, and it supports static members and other non-instance-oriented constructs.
02
What is the difference between a class and an object?
BeginnerClasses & objects
⌄

Answer

  1. A class defines a type; an object is an instance of that type.
  2. A class declares the fields and methods available to its instances.
  3. Each object normally has its own instance-field state.
  4. A reference variable stores a reference to an object, not the object’s full state directly.
  5. Many objects can be created from one class.
Follow-up: Can two references point to the same object?
Answer: Yes. Assigning one reference to another copies the reference value, so both can refer to the same object.
03
Explain encapsulation. Is it the same as data hiding?
BeginnerFour pillars
⌄

Answer

  1. Encapsulation combines state and related operations within a class.
  2. It controls access to internal state through access modifiers and methods.
  3. Data hiding is one technique that supports encapsulation, often using private.
  4. Validation in methods can preserve invariants, such as a nonnegative account deposit.
  5. Encapsulation reduces coupling between callers and implementation details.
Follow-up: Should every field have a setter?
Answer: No. Provide only operations that make sense for the object's rules; unrestricted setters can expose invalid states.
04
What is inheritance, and which types does Java support?
BeginnerFour pillars
⌄

Answer

  1. Inheritance lets a subclass extend a superclass using extends.
  2. It supports an “is-a” relationship and allows subclasses to specialize behavior.
  3. Java classes support single, multilevel, and hierarchical class inheritance.
  4. A class cannot directly extend multiple classes.
  5. A class can implement multiple interfaces, enabling multiple type contracts.
Follow-up: Are constructors inherited?
Answer: No. A subclass constructor can call a superclass constructor with super(...).
05
What is polymorphism? Explain compile-time and runtime polymorphism.
BeginnerFour pillars
⌄

Answer

  1. Polymorphism means one interface or operation can have multiple forms.
  2. Overloading is commonly called compile-time polymorphism.
  3. Overloaded methods have different parameter lists, and the compiler chooses the applicable method.
  4. Overriding supports runtime polymorphism for instance methods.
  5. At runtime, the actual object's class determines which override is executed.
Follow-up: Are fields polymorphic like overridden methods?
Answer: No. Field access is resolved using the compile-time reference type; instance method overrides use runtime dispatch.
06
What is abstraction? How does Java implement it?
BeginnerFour pillars
⌄

Answer

  1. Abstraction shows essential behavior while hiding implementation details.
  2. Abstract classes can include abstract and concrete methods, state, and constructors.
  3. Interfaces define contracts and can include abstract, default, static, and private methods within Java's rules.
  4. Clients can program to a type instead of depending on one implementation.
  5. Abstraction makes systems easier to extend and test when boundaries are well designed.
Follow-up: Can an abstract class be instantiated directly?
Answer: No, but a concrete subclass can be instantiated and referenced through the abstract type.
07
What is a constructor? How is it different from a method?
BeginnerConstructors
⌄

Answer

  1. A constructor initializes an object during creation.
  2. Its name matches the class name.
  3. It has no return type.
  4. It can be overloaded, but it is neither inherited nor overridden.
  5. A normal method can have any valid name, return a value, and be called after object creation.
Follow-up: What happens if you declare no constructor?
Answer: The compiler provides a default no-argument constructor only when the class declares no constructors.
08
Can we overload the main method in Java?
BeginnerMethods
⌄

Answer

  1. Yes, Java permits overloaded methods named main.
  2. Overloads can have different parameter lists.
  3. The standard launcher entry point is public static void main(String[] args) for conventional applications.
  4. Other overloads are not automatically selected as the launch entry point.
  5. Overloading does not mean changing only the return type.
Follow-up: Can main be overridden?
Answer: It is static, so a subclass can hide a static method with the same signature rather than override it.
09
What is the difference between method overloading and overriding?
IntermediateMethods
⌄

Answer

  1. Overloading uses the same method name with different parameter lists.
  2. Overloading does not require inheritance.
  3. Overriding replaces an inherited instance method implementation with a compatible signature.
  4. Overload selection is resolved at compile time; override dispatch is based on runtime type.
  5. Return type alone cannot create an overload; overriding permits covariant reference return types.
Follow-up: Can a static method be overridden?
Answer: No. Static methods are hidden, because they belong to the class rather than being dynamically dispatched instance methods.
10
Can an abstract class have a constructor and concrete methods?
IntermediateAbstraction
⌄

Answer

  1. Yes, an abstract class can declare constructors.
  2. Those constructors run as part of creating a concrete subclass object.
  3. It can define both abstract methods and fully implemented methods.
  4. It can maintain shared instance state.
  5. It cannot be instantiated directly with new AbstractType().
Follow-up: Why have a constructor if the class cannot be instantiated?
Answer: It initializes the superclass portion of a concrete subclass object.
11
Why does Java not support multiple inheritance of classes?
IntermediateInheritance
⌄

Answer

  1. Java allows a class to extend only one direct superclass.
  2. This avoids ambiguity in inheriting implementation and state from multiple class parents.
  3. The classic “diamond problem” illustrates possible ambiguity when two parents define the same behavior.
  4. Java provides interfaces for implementing multiple type contracts.
  5. Interfaces can have default methods, and conflicting inherited defaults may require an explicit resolution.
Follow-up: Can a class implement two interfaces with the same default method signature?
Answer: It may need to override the conflicting method and explicitly choose or combine the behavior.
12
What do this and super mean?
BeginnerKeywords
⌄

Answer

  1. this refers to the current object in an instance context.
  2. It commonly disambiguates a field from a parameter: this.name = name.
  3. this(...) delegates to another constructor in the same class.
  4. super accesses superclass behavior or fields when accessible.
  5. super(...) invokes a superclass constructor.
Follow-up: Can you use this inside a static method?
Answer: No, because a static method is not associated with a particular current instance.
13
What is the difference between == and equals() for objects?
IntermediateObject behavior
⌄

Answer

  1. For reference values, == checks whether references identify the same object.
  2. equals() checks logical equality as defined by the class.
  3. The default implementation inherited from Object behaves like identity comparison.
  4. Classes such as String override equals() to compare content.
  5. If you override equals(), you should also implement a consistent hashCode().
JAVA
String a = new String("java");
String b = new String("java");
System.out.println(a == b);
System.out.println(a.equals(b));
false true
Follow-up: Why must equal objects have equal hash codes?
Answer: Hash-based collections use the hash code to locate candidate buckets; violating the contract can make lookups behave incorrectly.
14
What is the purpose of static?
BeginnerKeywords
⌄

Answer

  1. A static field belongs to the class and is shared across instances.
  2. A static method can be called using the class name.
  3. A static method cannot directly access instance members without an object reference.
  4. Static methods are hidden, not overridden.
  5. Use static for behavior or state genuinely associated with the type, not as a default design choice.
Follow-up: Can a static method call an instance method directly?
Answer: Not without an object reference, because there is no implicit current instance.
15
What does final mean for variables, methods, and classes?
IntermediateKeywords
⌄

Answer

  1. A final variable can be assigned only once.
  2. A final reference cannot point to a different object after assignment, but the referenced object may still be mutable.
  3. A final method cannot be overridden.
  4. A final class cannot be subclassed.
  5. Final can express design constraints and support safer APIs, but does not automatically make an object immutable or thread-safe.
Follow-up: Is a final ArrayList immutable?
Answer: No. The reference cannot be reassigned, but elements can still be added or removed unless the list is otherwise restricted.
16
Can constructors be overloaded or overridden?
BeginnerConstructors
⌄

Answer

  1. Constructors can be overloaded with different parameter lists.
  2. Each constructor can initialize an object in a different way.
  3. Constructors are not inherited by subclasses.
  4. Because they are not inherited methods, they cannot be overridden.
  5. Constructor chaining can reuse initialization with this(...) or super(...).
Follow-up: Does a constructor return an object reference explicitly?
Answer: No. Object creation and reference delivery are handled by the creation expression; constructors have no return type.
17

19
What is composition, and why can it be preferable to inheritance?
IntermediateDesign

Answer

  1. Composition builds a class by giving it references to other objects it uses.
  2. It models a “has-a” relationship rather than an “is-a” relationship.
  3. It allows behavior to be swapped or combined without creating deep class hierarchies.
  4. It can reduce coupling to superclass implementation details.
  5. Inheritance remains appropriate when the subtype relationship is valid and substitutability is preserved.
Follow-up: Give an example of composition.
Answer: A Car has an Engine; the car delegates engine-related behavior to that object.
20
What is the relationship between equals() and hashCode()?
AdvancedObject contract

Answer

  1. If two objects are equal according to equals(), they must return the same hash code.
  2. Unequal objects may share a hash code; collisions are permitted.
  3. Hash-based collections use both hash codes and equality checks.
  4. Overriding one without the other can break expected collection behavior.
  5. Fields used for equality should be considered carefully, especially if they can change while an object is a map key.
Follow-up: Must unequal objects have different hash codes?
Answer: No. Different hash codes are useful but not required for unequal objects.
21
What is upcasting and downcasting?
IntermediateType relationships

Answer

  1. Upcasting assigns a subclass object to a superclass or interface reference and is generally implicit.
  2. It lets code work through a common abstraction.
  3. Downcasting converts a base reference to a more specific subtype reference.
  4. An invalid downcast throws ClassCastException at runtime.
  5. Use instanceof when a type check is necessary, and prefer polymorphism when it avoids casting.
Follow-up: Does upcasting remove the subclass object?
Answer: No. It changes the reference's static type, not the actual runtime object.
22
What is the difference between an association, aggregation, and composition?
IntermediateObject relationships

Answer

  1. Association is a general relationship between objects.
  2. Aggregation models a whole-part relationship where the part can live independently.
  3. Composition models stronger ownership, with the whole typically controlling the part's lifecycle.
  4. Examples are doctor-patient, team-player, and order-order-line, respectively.
  5. These are design concepts, not separate Java language keywords.
Follow-up: Does Java enforce composition automatically?
Answer: No. The design and lifecycle rules are implemented by the application code.

P2
Beginner: Use encapsulation to prevent a negative value from being set as a product price.
BeginnerCoding
⌄

Solution

JAVA
class Product {
    private double price;
    public void setPrice(double price) {
        if (price < 0) {
            throw new IllegalArgumentException("Price cannot be negative");
        }
        this.price = price;
    }
    public double getPrice() { return price; }
}
public class Main {
    public static void main(String[] args) {
        Product p = new Product();
        p.setPrice(99.5);
        System.out.println(p.getPrice());
    }
}
99.5

Explanation: The field is private. The setter validates before changing it. This teaching example allows zero and uses double; financial applications should generally use integer minor units or BigDecimal with a defined rounding policy.

P3
Intermediate: Create a Shape superclass and Circle subclass that override an area method.
IntermediateInheritance
⌄

Solution

JAVA
abstract class Shape {
    abstract double area();
}
class Circle extends Shape {
    private final double radius;
    Circle(double radius) {
        if (radius < 0) throw new IllegalArgumentException();
        this.radius = radius;
    }
    @Override double area() {
        return Math.PI * radius * radius;
    }
}
public class Main {
    public static void main(String[] args) {
        Shape s = new Circle(3);
        System.out.printf("%.2f%n", s.area());
    }
}
28.27

Explanation: Shape declares the contract. Circle implements it. The base reference invokes the concrete object's override at runtime. Time and space complexity for this constant-time area calculation are both O(1).

Advanced: Design a notification service that can send Email or SMS notifications without changing client logic.
AdvancedScenario
⌄

One possible solution

JAVA
interface Notifier {
    void send(String message);
}
class EmailNotifier implements Notifier {
    public void send(String message) {
        System.out.println("Email: " + message);
    }
}
class SmsNotifier implements Notifier {
    public void send(String message) {
        System.out.println("SMS: " + message);
    }
}
class AlertService {
    private final Notifier notifier;
    AlertService(Notifier notifier) { this.notifier = notifier; }
    void alert(String message) { notifier.send(message); }
}
public class Main {
    public static void main(String[] args) {
        new AlertService(new EmailNotifier()).alert("Build passed");
        new AlertService(new SmsNotifier()).alert("Build passed");
    }
}
Email: Build passed SMS: Build passed

Explanation: The service uses an interface rather than depending on one concrete notifier. Passing an implementation through the constructor is a simple form of dependency injection. A production notifier would also need error handling, retries, configuration, and secure credentials.

9. Mini mock interview

Practice answering aloud in 30–60 seconds, then compare your response with the model answer.

M1
Explain the four pillars using one sentence each.
  1. Encapsulation: Keep state and behavior together and control how state is changed.
  2. Inheritance: Create a specialized class from a more general class.
  3. Polymorphism: Use a common operation or parent type while allowing different implementations.
  4. Abstraction: Show the contract needed by a caller and hide implementation details.
  5. Example: a checkout service can use a PaymentMethod interface implemented by card and UPI payment classes.
M2
Why is Parent p = new Child(); useful?
  1. The reference is typed as Parent, while the object is a Child.
  2. It allows client code to depend on a general type.
  3. Overridden instance methods dispatch to the child's implementation.
  4. The code can work with different subclasses through the same API.
  5. The reference can only access members available through its compile-time type without casting.
M3
When would you choose an interface over an abstract class?
  1. Choose an interface when you need to define a capability or contract.
  2. It allows unrelated classes to share a common type.
  3. A class can implement multiple interfaces.
  4. Choose an abstract class when related subclasses need shared state or common implementation.
  5. Consider existing class hierarchy, API design, and expected extension points.
M4
How would you make a class safer to use?
  1. Keep fields private unless wider access is intentional.
  2. Validate inputs at the class boundary.
  3. Expose meaningful operations instead of arbitrary state mutation.
  4. Use immutable fields or immutable objects where practical.
  5. Document invariants and test invalid as well as valid cases.
