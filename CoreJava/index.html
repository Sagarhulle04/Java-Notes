01 · Foundations · Topic 01

Java Fundamentals

Java is a general-purpose, class-based programming language. You write source code, compile it to bytecode, and execute that bytecode on a Java Virtual Machine (JVM).

How a Java program runs

A .java file contains human-readable source code. The compiler (javac) checks it and produces platform-neutral bytecode in a .class file. A suitable JVM loads and executes that bytecode on the current operating system.

  • Source code: the program you write.
  • Bytecode: JVM instructions stored in class files.
  • JVM: runtime engine that interprets bytecode and may JIT-compile frequently used code into native machine code.

“Write once, run anywhere” means the same compatible bytecode can run wherever a suitable JVM exists; it does not mean every OS has identical behavior or every native dependency is portable.

Java example
public class HelloJava {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
Expected output / result
Hello, Java!
Interview tip / common mistake

A Java source file containing a public top-level class is conventionally saved with the same name: HelloJava.java. Compile with javac HelloJava.java, then run with java HelloJava (class name, not .class).

01 · Foundations · Topic 02

Features of Java

Java is popular because it combines a relatively simple syntax, object-oriented design, runtime checks, portability, and a mature standard library.

Platform independent

Bytecode runs on compatible JVMs.

Object-oriented

Programs organize behavior and state with classes and objects; primitives are not objects.

Robust

Strong type checking, exceptions, and managed memory help catch many errors.

Secure-minded

Bytecode verification, access controls, and runtime checks support safer execution; no language is automatically secure.

Multithreaded

Concurrent tasks can progress within one process.

Portable

Defined primitive sizes and bytecode help consistent behavior.

High performance

JIT compilation can optimize hot code at runtime.

Rich ecosystem

Libraries and tools support web, data, enterprise, Android-related, and server applications.

Be precise in interviews

Do not say Java is “purely object-oriented”: it has primitive types such as int and boolean. Do not claim Java has no pointers at all; normal Java code uses references rather than pointer arithmetic.

Java example
int items = 3;
String message = "Java has primitive and reference types.";
System.out.println(items);
System.out.println(message);
Expected output / result
3
Java has primitive and reference types.
Interview tip / common mistake

Avoid describing features as absolute guarantees. Security and robustness also depend on correct design, configuration, dependencies, and deployment.

01 · Foundations · Topic 03

JDK, JRE, and JVM

These three terms describe different layers: tools for development, the runtime libraries/environment, and the virtual machine that executes bytecode.

JDK — Java Development Kit

Development tools such as javac, debugger/tools, plus the runtime components needed by that JDK.

Runtime environment (JRE concept)

JVM + core libraries and supporting runtime files.

JVM

Loads, verifies, and executes bytecode; manages runtime memory and garbage collection.

Practical note: the JRE remains a useful conceptual term in interviews, but modern JDK distributions are not always delivered as a separate installable JRE in the older packaging style.

Java example
javac HelloJava.java   # compile with the JDK
java HelloJava         # launch through the JVM
Expected output / result
The compiler creates HelloJava.class; the Java launcher starts the JVM to run the class.
Interview tip / common mistake

Install a JDK to develop Java applications. The JVM is not the compiler, and the JDK is not merely another name for the JVM.

01 · Foundations · Topic 04

Java Architecture

Java architecture combines a compiler, class-loading process, bytecode verification, runtime memory areas, and an execution engine.

Major runtime parts

  • Class loader: finds and loads class definitions.
  • Bytecode verifier: checks structural and type-safety rules before execution.
  • Runtime data areas: heap, per-thread Java stacks and program counters, plus class/method metadata areas and native stacks as specified/implemented by the JVM.
  • Execution engine: interpreter and JIT compiler execute/optimize bytecode.
  • Garbage collector: reclaims heap objects that are no longer reachable.
  • JNI/native libraries: let Java interoperate with native code when required.
Java example
System.out.println(Runtime.getRuntime().availableProcessors());
System.out.println(System.getProperty("java.version"));
Expected output / result
The exact output depends on the machine and installed Java runtime.
Interview tip / common mistake

Do not equate Java architecture with only JVM/JRE/JDK. Also distinguish JVM specification rules from implementation details such as exact memory layout or JIT strategy.

02 · Language Basics · Topic 05

Comments, Identifiers, and Literals

Comments explain code to humans, identifiers name program elements, and literals are values written directly in source code.

Comments

  • // single-line comment
  • /* ... */ block comment
  • /** ... */ documentation comment, commonly used by Javadoc

Identifier rules

Identifiers are case-sensitive. They can use letters, currency symbols, connecting punctuation, and Unicode characters allowed by Java rules; they cannot start with a digit, contain ordinary spaces, or be a reserved keyword. Prefer readable conventional names.

Literal examples

42 integer, 3.14 double by default, 3.14f float, 'A' char, true boolean, "hello" String, null null reference.

Java example
// A line comment
int studentCount = 42;
double price = 99.50;
char grade = 'A';
String language = "Java";
System.out.println(language + ": " + studentCount);
Expected output / result
Java: 42
Interview tip / common mistake

Java naming conventions: classes use PascalCase; methods and variables use camelCase; constants are often UPPER_SNAKE_CASE. Naming convention is convention, not syntax.

Fields and array elements receive default values (for example numeric zero, false, or null). Local variables must be definitely assigned before use.

02 · Language Basics · Topic 07

Variables and Scope

A variable is a named storage location with a type. In Java, where a variable is declared determines its scope, lifetime, and whether it has a default value.

  • Local variable: declared inside a method, constructor, or block; available only in that scope and must be assigned before use.
  • Instance field: belongs to one object; every object has its own logical field value.
  • Static field: belongs to the class and is shared by its instances.
  • Parameter: receives a value when a method or constructor is called.

A variable's scope is where its name is accessible. A field's lifetime is associated with its object/class; a local variable is usable only within its scope.

Java example
class Counter {
    static int created = 0;     // class variable
    int value = 0;              // instance variable
    void increment() {
        int step = 1;            // local variable
        value += step;
    }
}

Counter a = new Counter();
Counter b = new Counter();
a.increment();
System.out.println(a.value + ", " + b.value);
System.out.println(Counter.created);
Expected output / result
1, 0
0
Interview tip / common mistake

The example shows that each instance has its own value; created is shared but does not increment automatically. Declare a counter update when an object is created if that is the intent.

02 · Language Basics · Topic 09

Type Casting and Type Conversion

Casting converts a value from one type to another. Widening conversions usually happen automatically; narrowing conversions require an explicit cast and may lose information.

Widening vs narrowing

Widening: for example int → long or int → double; generally implicit because the target can represent the source range/precision category, though floating-point conversion may still round large values.

Narrowing: for example double → int or int → byte; explicit and may truncate fractional parts or discard high-order bits.

Parsing is different: converting the text "123" to an integer uses a parsing method such as Integer.parseInt, not a cast.

Java example
int whole = 42;
double widened = whole;
double price = 19.95;
int truncated = (int) price;
int parsed = Integer.parseInt("123");
System.out.println(widened);
System.out.println(truncated);
System.out.println(parsed);
Expected output / result
42.0
19
123
Interview tip / common mistake

A cast does not round a fractional value: (int) 19.95 truncates toward zero. Use Math.round when rounding is intended. Parsing invalid text can throw NumberFormatException.

03 · Flow and Collections · Topic 10

Control Statements

Control statements decide which statements run: selection chooses a branch, iteration repeats work, and jump statements alter normal flow.

Selection

  • if, if-else, and else-if chains branch on boolean conditions.
  • switch selects among cases based on a supported selector type.

Jump statements

  • break exits the nearest loop or switch (or a labeled statement).
  • continue skips to the next iteration of a loop.
  • return exits a method, optionally returning a value.
Java example
int score = 76;
if (score >= 90) {
    System.out.println("A");
} else if (score >= 75) {
    System.out.println("B");
} else if (score >= 40) {
    System.out.println("Pass");
} else {
    System.out.println("Fail");
}
Expected output / result
B
Interview tip / common mistake

Conditions in an if statement must be boolean expressions; Java does not treat integers as truthy/falsy. Traditional switch cases can fall through without break; use the arrow-style switch syntax only when the project’s Java version supports it.

03 · Flow and Collections · Topic 11

Loops: for, while, do-while, enhanced for

Loops repeat a block of code. Choose the loop based on whether the number of repetitions is known and whether the body must execute at least once.

  • for: good when initialization, condition, and update belong together.
  • while: checks the condition before every iteration; may run zero times.
  • do-while: checks after the body; runs at least once.
  • Enhanced for: visits each element of an array or iterable; does not directly provide the index.
Java example
for (int i = 1; i <= 3; i++) {
    System.out.println("for: " + i);
}

int n = 3;
while (n > 0) {
    System.out.println("while: " + n);
    n--;
}

int attempts = 0;
do {
    attempts++;
} while (attempts < 1);
System.out.println("attempts=" + attempts);
Expected output / result
for: 1
for: 2
for: 3
while: 3
while: 2
while: 1
attempts=1
Interview tip / common mistake

Off-by-one errors are common: verify the start value, condition, and update. Ensure a while loop can eventually become false, or it may run forever.

03 · Flow and Collections · Topic 12

Arrays

An array stores a fixed-length sequence of values of one declared component type. Indexes start at zero.

  • Length is fixed after creation and read with array.length (not length()).
  • Primitive arrays hold primitive values; reference arrays hold references to objects.
  • Array elements receive default values.
  • Accessing an invalid index throws ArrayIndexOutOfBoundsException.
  • A 2D array is an array of arrays, so rows can have different lengths (a jagged array).
Java example
int[] marks = {82, 91, 76};
int sum = 0;
for (int mark : marks) {
    sum += mark;
}
System.out.println("count=" + marks.length);
System.out.println("sum=" + sum);
System.out.println("average=" + (sum / (double) marks.length));
Expected output / result
count=3
sum=249
average=83.0
Interview tip / common mistake

Array indexes are 0 through length - 1. Do not confuse array length with the number of non-zero values. An array can contain null references when its component type is a reference type.

04 · Strings and Objects · Topic 14

String Immutability

String objects cannot be changed after creation. Operations that appear to modify a String create or return another String value instead.

Immutability makes Strings safe to share, simplifies use as map keys, and supports string-pool reuse. It does not mean a variable that refers to a String can never be reassigned.

For repeated edits in a loop, prefer StringBuilder to avoid creating many intermediate String objects. StringBuffer offers synchronized methods but is often unnecessary in ordinary single-threaded string-building code.

Java example
String name = "Java";
name.concat(" Notes");
System.out.println(name);
name = name.concat(" Notes");
System.out.println(name);

StringBuilder builder = new StringBuilder("Java");
builder.append(" Notes");
System.out.println(builder);
Expected output / result
Java
Java Notes
Java Notes
Interview tip / common mistake

The first concat() result is ignored, so name still refers to "Java". Assign the returned String if you want to retain the result.

04 · Strings and Objects · Topic 15

String Constant Pool

The String pool allows equal String literals and appropriately interned Strings to share canonical instances, saving memory for repeated text.

String literals are interned by the Java runtime. The intern() method returns the canonical pooled String for the same contents. The pool’s implementation/storage details have changed across Java versions; for interviews, focus on reference behavior rather than memorizing a physical memory location.

Using new String("Java") explicitly requests a distinct String object even though the literal content is pooled. Avoid using == when checking text content.

Java example
String a = "Java";
String b = "Java";
String c = new String("Java");
String d = c.intern();
System.out.println(a == b);
System.out.println(a == c);
System.out.println(a.equals(c));
System.out.println(a == d);
Expected output / result
true
false
true
true
Interview tip / common mistake

Do not depend on == behaving like content equality. Results can differ based on literal interning, construction, and whether intern() is used.

04 · Strings and Objects · Topic 16

Wrapper Classes

Wrapper classes provide object representations of primitive values, enabling primitives to be used where objects are required.

Wrapper objects are immutable. Collections such as ArrayList<Integer> use reference types, so you use wrappers rather than primitive type arguments.

Java example
int number = Integer.parseInt("250");

System.out.println(number + 10);
System.out.println(boxed);
System.out.println(Character.isDigit('7'));

Use parseInt when you need an int primitive; valueOf returns an Integer. Invalid numeric text throws NumberFormatException.

04 · Strings and Objects · Topic 17

Autoboxing and Unboxing

Autoboxing automatically converts a primitive to its wrapper type; unboxing converts a wrapper object back to a primitive.

Autoboxing is syntactic convenience, not a promise that wrapper references compare by value with ==. Also, unboxing a null wrapper throws NullPointerException.

Integer caching is guaranteed for the values from -128 through 127; implementations may cache more. Never use wrapper identity as a substitute for numerical equality.

Java example
Integer count = 5;  // autoboxing: int -> Integer
int total = count;    // unboxing: Integer -> int
System.out.println(total + 1);

Integer missing = null;
// int value = missing; // throws NullPointerException
Expected output / result
6
Interview tip / common mistake

Beware nullable database/API values. Check a wrapper for null before unboxing, or use an explicit default where appropriate.

05 · Runtime and Structure · Topic 18

Command-Line Arguments

The Java launcher passes command-line arguments to the program through the String array parameter in the main method.

Each command-line token becomes one element in args. Shell quoting and escaping rules determine how text is split before Java receives it. The first command-line argument is args[0], not args[1].

Arguments arrive as Strings. Parse numeric arguments and validate that the expected number was supplied.

Java example
public class Greet {
    public static void main(String[] args) {
        if (args.length == 0) {
            System.out.println("Usage: java Greet <name>");
            return;
        }
        System.out.println("Hello, " + args[0]);
    }
}
Expected output / result
Command: java Greet Sagar
Output: Hello, Sagar
Interview tip / common mistake

Argument values are not automatically converted to integers. Use Integer.parseInt(args[0]) with argument-count and input validation for numeric parameters.

05 · Runtime and Structure · Topic 19

Input and Output Basics

Java console programs usually print with System.out and read input using Scanner or BufferedReader.

Common tools

  • System.out.print(): print without a newline.
  • System.out.println(): print and end the line.
  • System.out.printf(): formatted output such as %.2f for two decimal places.
  • Scanner: convenient token and line parsing, suitable for beginner exercises.
  • BufferedReader: efficient character input; numeric strings must be parsed.

Scanner's nextInt() followed by nextLine() may appear to skip a line because the newline after the number remains in the input. Consume the rest of that line when mixing these methods.

Java example
import java.util.Scanner;

Scanner sc = new Scanner(System.in);
System.out.print("Name: ");
String name = sc.nextLine();
System.out.print("Marks: ");
int marks = Integer.parseInt(sc.nextLine());
System.out.printf("%s scored %d marks.%n", name, marks);
Expected output / result
Example input:
Name: Sagar
Marks: 88
Example output:
Sagar scored 88 marks.
Interview tip / common mistake

This snippet is intended inside a class/method with imports at the top. For production code, plan resource ownership before closing System.in; closing a Scanner wrapping it closes the underlying input stream. Use try-with-resources for streams/files your code owns.

05 · Runtime and Structure · Topic 20

Packages and import

Packages group related types, prevent many naming conflicts, and help define access boundaries.

  • A package declaration, when present, appears before imports and type declarations (comments may precede it).
  • import lets code use a type's simple name; importing does not copy the class into the project.
  • java.lang is imported automatically.
  • Subpackages are separate packages: com.app and com.app.util do not share package-private access.
  • Directory layout usually mirrors package names, for example com/example/app/Main.java.
Java example
package com.example.app;

import java.util.ArrayList;

public class Main {
    public static void main(String[] args) {
        ArrayList<String> names = new ArrayList<>();
        names.add("Sagar");
        System.out.println(names);
    }
}
Expected output / result
[Sagar]
Interview tip / common mistake

A package name is not the same as the import statement. If a source file declares a package, compile/run it from a setup that respects that package structure.

05 · Runtime and Structure · Topic 21

Access Modifiers

Access modifiers control where classes, fields, constructors, and methods can be accessed.

ModifierSame classSame packageSubclass in another packageUnrelated outside package
publicYesYesYesYes (subject to enclosing type/module accessibility)
protectedYesYesYes, through subclass rulesNo
package-private (no keyword)YesYesNoNo
privateYesNoNoNo

Top-level classes can be public or package-private; they cannot be private or protected. Nested classes can use all four.

Java example
public class Account {
    private double balance;

    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    public double getBalance() {
        return balance;
    }
}
Expected output / result
The class has no console output by itself. Clients can call deposit() and getBalance(), but cannot access balance directly.
Interview tip / common mistake

For protected access across packages, access must follow Java’s subclass rules; it is not simply “public to all subclasses” in every reference expression. Encapsulation usually favors private fields and controlled public methods.

06 · Keywords and Method Semantics · Topic 22

static Keyword

A static member belongs to the class rather than to an individual instance. One static field is shared by instances of that class.

  • Static field: class-level state.
  • Static method: called using the class name; it has no implicit this reference.
  • Static initializer: runs when the class is initialized.
  • Static nested class: nested type not requiring an enclosing instance.

A static method cannot directly use an instance field/method without an object reference. Use ClassName.member for clarity when calling static members.

Java example
class User {
    static int count = 0;
    User() { count++; }
}

new User();
new User();
new User();
System.out.println(User.count);
Expected output / result
3
Interview tip / common mistake

Do not declare every helper as static automatically. Use instance members when behavior/state belongs to one object; use static members for class-level behavior or state.

06 · Keywords and Method Semantics · Topic 23

final Keyword

The final keyword prevents reassignment of a variable, overriding of a method, or inheritance from a class, depending on where it is used.

  • final variable: can be assigned only once (a blank final field must be assigned along every valid constructor path).
  • final method: subclasses cannot override it.
  • final class: cannot be subclassed, as with String.

A final reference cannot be redirected to another object, but the referenced object may still be mutable. final is not the same as immutable.

Java example
final int maxAttempts = 3;
System.out.println(maxAttempts);

final StringBuilder log = new StringBuilder();
log.append("started");
System.out.println(log);
// log = new StringBuilder(); // compile-time error
Expected output / result
3
started
Interview tip / common mistake

Do not claim a final object reference makes the object immutable. It prevents reassignment of the reference, not calls that mutate the object.

06 · Keywords and Method Semantics · Topic 24

this Keyword

The keyword this refers to the current object in an instance context.

  • Distinguishes a field from a parameter with the same name.
  • Calls another constructor in the same class using this(...).
  • Can pass or return the current object.
  • Cannot be used in a static context because no current instance is implied.

A constructor call using this(...) must be the first statement in the constructor body.

Java example
class Student {
    String name;
    int year;

    Student(String name, int year) {
        this.name = name;
        this.year = year;
    }
}
Student s = new Student("Sagar", 2026);
System.out.println(s.name + " " + s.year);
Expected output / result
Sagar 2026
Interview tip / common mistake

this.name = name means “set this object’s field from the parameter.” Parameter names can be different, but this syntax resolves shadowing clearly.

06 · Keywords and Method Semantics · Topic 25

super Keyword

The keyword super refers to the superclass part of the current object and is used to call a parent constructor or access an accessible superclass implementation/member.

  • super(...) invokes a superclass constructor.
  • super.method() calls the superclass implementation of an overridable method.
  • super.field refers to an accessible hidden superclass field.

If no explicit this(...) or super(...) constructor invocation is written, Java inserts a no-argument superclass constructor invocation when applicable. If the superclass has no accessible no-argument constructor, the subclass must explicitly call a suitable constructor.

Java example
class Animal {
    Animal(String name) {
        System.out.println("Animal: " + name);
    }
}
class Dog extends Animal {
    Dog() {
        super("Dog");
        System.out.println("Dog created");
    }
}
new Dog();
Expected output / result
Animal: Dog
Dog created
Interview tip / common mistake

Constructor invocation using super(...) must be first in a traditional constructor body. A constructor itself is not inherited.

06 · Keywords and Method Semantics · Topic 26

The main Method

The conventional Java application entry point is public static void main(String[] args). The launcher looks for a supported entry-point signature in the class being launched.

public allows the launcher to access it; static means it can run without first constructing an object; void means it returns no value; String[] args receives command-line arguments. The parameter name args can be changed, but its type/signature matters.

For placement preparation, know the classic signature well. Java launcher capabilities can evolve across releases, but do not assume an arbitrary method such as start() or a method with a different parameter type is the entry point.

Java example
public class Main {
    public static void main(String[] args) {
        System.out.println("Application starts here");
    }
}
Expected output / result
Application starts here
Interview tip / common mistake

The capitalization is exact: String, System, and main. Main() is a constructor, not the main method.

06 · Keywords and Method Semantics · Topic 27

Pass by Value in Java

Java is always pass-by-value. A method receives a copy of the argument value; when the value is an object reference, the reference value is copied.

Primitive argument: the method receives a copy of the primitive value; changing its parameter does not change the caller’s variable.

Object reference argument: the method receives a copy of the reference. It can mutate the same object through that reference, so the caller can observe the mutation. Reassigning the local parameter to a different object does not reassign the caller’s variable.

Java example
static void changeNumber(int x) { x = 99; }
static void rename(StringBuilder b) {
    b.append(" Java");
    b = new StringBuilder("Other");
}

int n = 10;
changeNumber(n);
StringBuilder text = new StringBuilder("Core");
rename(text);
System.out.println(n);
System.out.println(text);
Expected output / result
10
Core Java
Interview tip / common mistake

Do not say objects are passed by reference in Java. The reference is passed by value; this wording explains both mutation visibility and why local reassignment does not affect the caller’s variable.

07 · Additional Core Topics · Topic 28

Methods, Parameters, and Return Values

A method packages reusable behavior. Its declaration includes modifiers, a return type, a name, parameters, and a body.

Parameters receive input; a non-void method returns a value with return. A method’s signature for overload resolution includes its name and parameter types (with the appropriate type-variable/parameter details); return type alone cannot distinguish overloads.

Overloading

Several methods can share a name if their parameter lists differ. Changing only the return type is not enough. Varargs (type... values) allow zero or more arguments of that type and behave like an array parameter.

Java example
static int add(int a, int b) {
    return a + b;
}
static double add(double a, double b) {
    return a + b;
}
System.out.println(add(3, 4));
System.out.println(add(1.5, 2.5));
Expected output / result
7
4.0
Interview tip / common mistake

If the compiler sees ambiguous overloaded calls, it reports a compile-time error. Prefer overloads whose intent is clear and avoid overloads that differ only in confusing primitive/wrapper combinations.

07 · Additional Core Topics · Topic 29

Memory Management and Garbage Collection

Java manages memory for ordinary objects through garbage collection (GC). GC can reclaim objects that are no longer reachable from live program roots.

Reachability: an object is eligible for collection when it can no longer be reached through live references from roots such as active threads, static references, and JVM-managed references. Eligibility does not mean collection happens immediately.

GC does not automatically close files, sockets, database connections, or other external resources. Use try-with-resources or explicit lifecycle management for resources that implement AutoCloseable.

System.gc() is only a request/hint; the JVM is not required to perform collection at that moment. Avoid relying on finalization for cleanup; finalization is deprecated for removal in modern Java.

Java example
Object obj = new Object();
obj = null;
// The previously referenced object may now be eligible for GC.
System.out.println("Reference cleared");
Expected output / result
Reference cleared
Interview tip / common mistake

Setting one reference to null is not proof the object will be collected: another live reference may still point to it. GC timing is nondeterministic.

07 · Additional Core Topics · Topic 30

Stack vs Heap Memory

The Java runtime uses per-thread stacks for method-call frames and a heap for objects and arrays. Exact implementation layout is JVM-dependent, but the conceptual distinction is essential.

Thread stack

  • Each thread has its own stack.
  • Method frames hold local variables, intermediate values, and return/exception bookkeeping (implementation details vary).
  • Frames are pushed on calls and removed on return.
  • Excessive recursion can cause StackOverflowError.

Heap

  • Shared runtime area used for objects and arrays.
  • Object state can be accessed by multiple threads if references are shared.
  • Garbage collection reclaims unreachable managed objects.
  • Memory exhaustion can cause OutOfMemoryError.

A local reference can live in a stack frame while the object it refers to lives on the heap. Do not state that every local variable or every object must physically live in a particular memory region in every optimizing JVM implementation.

Java example
class Box { int value = 7; }
Box makeBox() {
    Box b = new Box(); // b is a local reference; Box object is an object
    return b;
}
Expected output / result
This is a method example, not a complete runnable class. Returning the reference lets the caller continue to reach the Box object after the method returns.
Interview tip / common mistake

The stack is not the same as “primitive memory,” and the heap is not the same as “reference memory.” A stack frame can contain a reference to an object on the heap.

07 · Additional Core Topics · Topic 31

Exception Handling Basics

An exception represents an abnormal condition that disrupts normal program flow. Java’s try/catch/finally and try-with-resources constructs help handle failures and cleanup.

  • Checked exceptions: compiler requires handling or declaration (subject to rules), e.g. IOException.
  • Unchecked exceptions: subclasses of RuntimeException, e.g. IllegalArgumentException and NullPointerException.
  • Error: serious JVM/environment conditions, generally not ordinary application recovery targets.
  • throw throws an exception instance; throws declares possible exceptions in a method signature.
  • finally usually runs after try/catch control flow, but abrupt JVM/process termination can prevent it.
Java example
try {
    int value = Integer.parseInt("not-a-number");
    System.out.println(value);
} catch (NumberFormatException ex) {
    System.out.println("Please provide a valid integer.");
} finally {
    System.out.println("Validation finished.");
}
Expected output / result
Please provide a valid integer.
Validation finished.
Interview tip / common mistake

Catch specific exceptions that you can handle meaningfully. Avoid empty catch blocks and avoid catching Throwable for ordinary application logic.

07 · Additional Core Topics · Topic 32

Enums and Type-Safe Constants

An enum defines a fixed set of named constants. It makes a variable’s allowed values clear and is safer than scattering arbitrary String values throughout code.

Enum constants are instances of the enum type. Enums can have fields, constructors, and methods. They can be used in switch statements and can implement interfaces, but cannot extend another class because every enum already extends java.lang.Enum.

Java example
enum Status { NEW, IN_PROGRESS, DONE }
Status taskStatus = Status.IN_PROGRESS;
switch (taskStatus) {
    case NEW -> System.out.println("Not started");
    case IN_PROGRESS -> System.out.println("Working");
    case DONE -> System.out.println("Finished");
}
Expected output / result
Working
Interview tip / common mistake

The arrow switch syntax shown requires a modern Java version (Java 14+ as a standard feature). For older syllabuses, use traditional case labels with break.

Core Java Interview Questions & Answers

Use these as spoken answers: start with the definition, then add one precise distinction or example. Expand a question to reveal the interview-ready answer.

Q01What is Java?+

Java is a class-based, general-purpose language. Source code is compiled to bytecode, and a compatible JVM loads and executes that bytecode on a target platform.

Q02What does platform independent mean?+

The compiled bytecode is designed to run on any platform with a compatible JVM. The JVM itself is platform-specific, and native dependencies can reduce portability.

Q03Differentiate JDK, JRE, and JVM.+

JDK provides development tools plus runtime components; the JRE is the conceptual runtime environment containing the JVM and libraries; JVM loads, verifies, and executes bytecode.

Q04Is Java purely object-oriented?+

No. Java supports object-oriented programming but also has primitive types such as int, char, and boolean, which are not objects.

Q05What is bytecode?+

Bytecode is the platform-neutral instruction set stored in class files by the Java compiler and executed by a JVM.

Q06What is the role of JIT?+

The Just-In-Time compiler can compile frequently executed bytecode into native machine code at runtime to improve performance.

Q07List the eight primitive types.+

byte, short, int, long, float, double, char, and boolean.

Q08Why must a local variable be initialized?+

Java’s definite-assignment rules require the compiler to prove a local variable has a value before it is read. Fields and array elements get default values.

Q09What is the difference between == and equals()?+

For primitives, == compares values. For references, == checks identity (same object). equals() checks logical equality if the class provides an appropriate override.

Q10What is type casting?+

Casting converts a value from one type to another. Widening is often implicit; narrowing often requires an explicit cast and can lose information.

Q11Why is 7 / 2 equal to 3?+

Both operands are integers, so integer division discards the fractional part toward zero. Use 7.0 / 2 or cast an operand to floating point for a fractional result.

Q12What is short-circuit evaluation?+

With &&, if the left operand is false, the right operand is not evaluated. With ||, if the left operand is true, the right operand is not evaluated.

Q13What is the difference between while and do-while?+

while checks before executing and may run zero times. do-while checks after the body and runs at least once.

Q14What is an array?+

An array is a fixed-length indexed sequence of components of one declared type. Indexing starts at zero.

Q15Why is String immutable?+

A String’s content cannot be changed after creation. This supports safe sharing and pooling and simplifies equality/hash behavior; operations return new Strings.

Q16What is the String Constant Pool?+

It is the runtime mechanism for reusing canonical String instances, especially literals. intern() returns the canonical pooled instance for the contents.

Q17Difference between String, StringBuilder, and StringBuffer?+

String is immutable. StringBuilder is mutable and generally preferred for repeated single-threaded construction. StringBuffer has synchronized methods for thread-safe operations on that buffer.

Q18What are wrapper classes?+

Classes such as Integer, Double, and Boolean represent primitive values as objects, useful in generics/collections and APIs requiring references.

Q19What is autoboxing?+

Automatic conversion from a primitive to its wrapper type, such as int to Integer. Unboxing converts the wrapper to the primitive and can throw NullPointerException if the wrapper is null.

Q20What are command-line arguments?+

Strings passed by the launcher to main via String[] args. Check args.length and parse values as needed.

Q21What is a package?+

A namespace that groups related types, helps avoid name conflicts, and establishes package-level access boundaries.

Q22Explain Java access modifiers.+

public is broadly accessible; protected supports same-package access and subclass access; package-private has no keyword and is package-only; private is class-level access only, including the declaring top-level class’s nested members under Java’s nest access rules.

Q23What does static mean?+

The member belongs to the class rather than one instance. A static method has no implicit this reference and cannot directly access instance members.

Q24What does final mean?+

A final variable can be assigned once; a final method cannot be overridden; a final class cannot be subclassed. A final reference does not guarantee that the referenced object is immutable.

Q25What is this?+

this refers to the current instance. It helps distinguish fields from parameters and can delegate construction with this(...).

Q26What is super?+

super accesses the superclass implementation/member or invokes a superclass constructor. A constructor call to super(...) must be first in a traditional constructor body.

Q27Why is main static?+

The conventional launcher entry point is static so the runtime can invoke it without first creating an instance of the application class.

Q28Is Java pass-by-reference?+

No. Java is pass-by-value. A copied reference can still reach and mutate the same object, but reassignment of the local parameter does not reassign the caller variable.

Q29What is garbage collection?+

GC reclaims managed objects that are no longer reachable from live roots. Eligibility and collection timing are nondeterministic.

Q30Stack vs heap?+

Each thread has a stack of method frames. The heap is the shared runtime area used for objects/arrays. A stack local may hold a reference to a heap object.

Q31Can we overload a method by changing only its return type?+

No. Overloads need distinguishable parameter lists; return type alone cannot resolve a call.

Q32What is the difference between break and continue?+

break exits the nearest loop or switch; continue skips the rest of the current loop iteration and proceeds to the next iteration.

Q33What is the difference between throw and throws?+

throw is a statement that throws an exception object. throws is part of a method declaration that specifies exceptions the method can propagate.

Q34What is a checked exception?+

A checked exception is a Throwable subtype other than RuntimeException/its subclasses and Error/its subclasses; Java requires it to be caught or declared when it can be thrown under compile-time rules.

Q35Can a final object be changed?+

Its reference cannot be reassigned, but the object can be mutated if its class exposes mutating operations. final reference does not mean deep immutability.

Q36What is integer overflow?+

Integer arithmetic can exceed a type’s representable range; ordinary int/long overflow wraps according to two’s-complement arithmetic rather than automatically throwing an exception.

Q37What is the difference between parseInt and valueOf?+

Integer.parseInt(String) returns an int primitive. Integer.valueOf(String) returns an Integer object (and may reuse cached instances).

Q38Why should we avoid == for Integer values?+

Wrapper identity can be affected by caching for a guaranteed small range and implementation choices beyond it. Compare numerical values by unboxing or equals(), with null safety as needed.

Q39What is an enum?+

An enum defines a fixed set of typed constants. It improves readability and prevents arbitrary values from being used where a known state is expected.

Q40What is try-with-resources?+

A try statement that automatically closes declared AutoCloseable resources when control exits the block, including exceptional exits.
